# 自律追踪

一个只有 4 个页面的本地戒断追踪工具。不联网、不注册、不打包，双击 `index.html` 就能用。

可以同时追踪好几个项目（戒熬夜、戒短视频、戒夜宵……），每个项目各自计时、各自统计，也可以合起来看。

> 记录不是定罪，是采集样本。

## 怎么打开

**电脑**：双击 `index.html`（推荐 Edge 或 Chrome）。也可以直接拖进浏览器窗口。

**手机**：把整个文件夹放到一个网址上，然后用手机浏览器打开（`file://` 在 iOS 上走不通，安卓可以但体验差）。托管步骤见下面「[部署到手机](#部署到手机)」，全程免费，只要一个账号。

窗口够宽时会自动变成桌面版式（左侧导航栏 + 两栏内容）；手机上仍然是单列，底部 Tab。

## 四个页面

| 页面      | 干什么                                                                         |
| ------- | --------------------------------------------------------------------------- |
| **首页**  | 只回答一件事：每个项目这次坚持了多久。单项目时是大圆环 + 大数字；多项目时是每个项目一张卡，牌面就是它的连续天数、下一次里程碑、进度条和「我没忍住」 |
| **统计**  | 原因分布、高危时段（7×24 热力图）、坚持时长趋势、全年日历热力。多项目时顶部一排范围切换：全部 / 单个项目。目标是从数据里找规律，不是找罪名   |
| **时间线** | 每次记录按月倒序排开，多项目时带项目色点。点任意一条看详情，也能删掉记错的                                       |
| **设置**  | 项目管理（新增 / 改名 / 换色 / 改开始日期 / 归档 / 删除）、切换主题、导出/导入备份、清空数据                      |

宽屏上首页右栏还会多一张「最近三次」卡，点里面的「查看全部」直接跳到时间线。

## 多个项目

一开始只有一个项目（叫「戒断项目」），改个名就能用。想加第二个：首页底部或设置页里的「**＋ 新增项目**」，填名字、挑个颜色（9 种可选）、选一个开始日期。

- **各自独立**：每个项目有自己的连续天数、里程碑、记录和统计。今天戒熬夜破了不影响戒短视频的计时
- **统计可以合看**：统计页和时间线顶部有范围条，「全部」是把所有项目合起来算，点某个项目就只看它
- **归档 ≠ 删除**：戒成了的项目可以在它的编辑面板里「归档」，它就不再占首页位置、记录全部保留（还在「全部」的统计里）。想找回来在设置页的「已归档」里点开恢复
- **删除会连记录一起删**：二次确认里会告诉你要删掉多少条，删了就回不来
- **至少留一个项目**：最后一个项目不能删也不能归档，这是为了防止首页变成空的

数据上每个项目是 `habits` 数组里的一项，每条记录靠 `habitId` 归属到项目。旧版本（只有一个目标）的数据读进来会自动可用，一条记录都不会丢。

## 记录一次破戒

点首页的「**我没忍住**」（多项目时点对应项目卡上的那一个，面板顶部会标出是哪个项目），两屏：

1. **这次是怎么了** —— 多选原因标签（失眠 / 压力大 / 无聊空虚 / 情绪低落 / 刷到触发内容……）。没有合适的可以自己加一个，加过的会一直留着
2. **当时在哪** —— 场景单选（床上 / 洗手间 / 独自在家……）、心情 1-5 档、一句话复盘

两屏的标签都能改：点「管理」，标签上会冒出一个 ×，点一下就从列表里去掉（内置的会进「恢复默认」）；底下的输入框加一个自己的，加完自动选中。想放到设置里统一管也行——设置 → 自定义原因 / 自定义场景。改标签只是不再显示新选项，**以前记录里的标签照旧保留，统计也照旧算**。

也可以只选原因直接保存，不逼你写作文。记完计时器归零，重新开始算。

写清楚一点的好处：统计页的原因分布和高危时段就靠这些标签。写「压力大」比写「就是没忍住」有用得多——前者能让你发现「每次加班当天晚上九点最危险」。

## 部署到手机

任意静态托管都行，产物就是一个文件夹（`index.html` + `sw.js` + `css/` + `js/` + `manifest.json` + `icon.svg`）。注意 `sw.js` **必须放在根目录**（它决定 service worker 的作用范围），别漏传。下面两条路，选一条。

### 路线 A：Netlify Drop（最快，几分钟）

1. 打开 <https://app.netlify.com/drop>
2. 把**整个项目文件夹**拖进页面上的虚线框（不要只拖 `index.html`）
3. 上传完它会给你一个 `https://随机名字.netlify.app` 的网址
4. **马上点页面上的 Claim（认领）并注册/登录一个免费账号** —— 匿名部署是临时的：认领窗口只有一个小时，而且没认领的站点默认带访问密码，手机打不开
5. 认领后这个网址就是永久的。手机浏览器打开它 → 菜单里选「添加到主屏幕」

### 路线 B：GitHub Pages

1. 新建一个仓库（Public）
2. 把 `自律追踪` 文件夹里的这些东西上传/推送上去：`index.html`、`sw.js`、`manifest.json`、`icon.svg`、`css/`、`js/`、`README.md`、`PLAN.md`、`_dev/`（`node_modules` 已被 `.gitignore` 排除）
3. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存
4. 等一两分钟，网址是 `https://你的用户名.github.io/仓库名/`
5. 手机打开这个网址 → 「添加到主屏幕」

**上传时别带的**（`.gitignore` 已经写好，用 git 就自动跳过；用网页拖拽要手动避开）：

- `_dev/node_modules/` —— 20MB、1800+ 个文件，拖进网页会卡住甚至失败，而且完全是本地开发用的
- `自律追踪.zip` —— 打包产物，内容就是上面那些文件

以后改了代码，**不用整包重传**，只把动过的文件覆盖上去就行（这次只动了 `js/` 下 3 个文件、`css/components.css`、`README.md`）。用 git 的话更省事：`git add -A && git commit -m "..." && git push`，它自己算差异。

> 换网址 = 换存储空间。如果你之前已经在别的网址（比如 Netlify）记过数据，先在那里「导出备份」，再在新网址「导入备份」，否则新站点是从零开始的。

### 添加到主屏幕（重要，和你的数据有关）

- **iOS Safari**：分享按钮 → 「添加到主屏幕」。加完从主屏幕图标打开，全屏、没有地址栏，更像 App
- **Android Chrome**：右上角菜单 → 「添加到主屏幕」/「安装应用」

必须加，原因见下一节。

### 改了代码，手机上什么时候能看到新版

以前是「看 iOS 心情」：主屏幕那个图标的独立 webview 缓存极顽固，文件都换好了手机上还是旧的，得删图标重加、甚至清网站数据（连记录一起清）。**现在有 `sw.js` 兜着，不用再折腾**。

`sw.js` 是 network-first 策略的 service worker：

1. 每次打开 → 先向服务器要一份最新的 `index.html` 和各个 `js/css`（带 `cache: 'no-cache'`，走 ETag 校验，没改就 304，不会白下载）
2. 拿到新的 → 顺手写进缓存
3. 网络不给力 / 离线 → 回落到上一次缓存的那份，页面照常打开

于是：`git push` → 等 GitHub Pages 部署完（仓库 **Actions** 里那条约 30 秒~2 分钟变绿）→ 手机上**把 App 划掉重开**就是新版。

几个配套细节：

- 第一次带 SW 的版本，需要**加载一次**让它装上，之后才生效
- 如果以后想强制所有人重来一遍：把 `sw.js` 顶部的 `const CACHE = 'selfdiscipline-v1'` 版本号 +1，旧缓存会在激活时被整体删掉
- 别把策略改成 cache-first —— 那会永久卡在旧版，改完 push 都不生效
- 本地双击 `index.html`（`file://`）不注册 SW，这是浏览器限制，不影响开发；想本地测 SW 就 `python -m http.server` 起一个

### 改了代码重新部署，数据会丢吗

不会，只要**网址（域名）没变**。你的记录存在浏览器里、按网址区分，重新上传文件只是换掉文件，动不到记录。

会丢的情况只有三种：换了新网址（新站点 = 新的存储空间，从零开始）、清了浏览器数据、换了一台设备。前两种只能靠备份兜底。

## 数据存在哪里

**只存在你打开它的那个浏览器的 `localStorage` 里**，key 是 `selfdiscipline.v1`。服务器上什么都不存 —— 托管只是把文件放上网，你的记录从来没离开过手机。

这意味着：

- 换浏览器、换设备，数据不会跟过去（手机和电脑各存各的，不互通）
- 清理浏览器数据（尤其「Cookie 和网站数据」）会把它一起清掉
- 无痕窗口里的记录关掉就没了
- **iOS 有个坑**：没「添加到主屏幕」的站点，Safari 在 7 天不访问后会清掉它的本地存储。加成主屏幕 App 后不受这条限制 —— 所以上面那步别省

所以在设置页点「**导出备份**」会下载一个 JSON 文件，把它丢进网盘/微信收藏，就是最稳的保险。设置页会显示「上次备份」是几天前；超过 14 天没备份，首页底部会提醒你一次。

换设备时在新设备上「导入备份」就能全部恢复。这是唯一的跨设备迁移方式，也是唯一的可靠备份。

## 文件结构

```
index.html            单页骨架 + 底部（宽屏是左侧）导航
sw.js                 service worker：network-first，保证上传的新版能被手机拿到
manifest.json         添加到主屏幕用的应用信息
icon.svg              应用图标
css/tokens.css        颜色、圆角、动效曲线等设计令牌（亮/暗两套）
css/base.css          布局：手机比例居中列、页面进入动画
css/components.css    卡片、按钮、标签、Sheet、图表、时间线等组件样式
css/desktop.css       分栏容器 + 宽屏版式（最后加载，覆盖前面）
js/store.js           数据层：读写 localStorage、日期口径、所有统计计算
js/ui.js              DOM 小工具、分栏容器、底部 Sheet、确认框、toast
js/charts.js          手写 SVG 图表：进度环、条形图、热力图、折线、日历
js/views-*.js         四个页面各自的渲染逻辑
js/app.js             hash 路由 + 每秒心跳 + 跨天自动重绘
PLAN.md               最初的产品与技术规划
_dev/                 开发期自检脚本，不参与产品运行，可以整个删掉
```

技术上刻意选了零依赖零构建：没有 `type="module"`（`file://` 下会被 CORS 拦），所有脚本按顺序加载，共用一个 `window.SD` 命名空间。改完直接刷新浏览器就生效，没有编译步骤。

布局用 `SD.ui.columns([左栏节点], [右栏节点])` 表达：宽屏分两栏，手机上按「左栏 → 右栏」的顺序单列堆叠。只想要单列收窄的页面（时间线）套一个 `.desk-single`。

## 开发自检

`_dev/` 里是几份跑在 Node 上的检查脚本。跑之前需要在 `_dev` 里装一次 jsdom（只有界面相关的检查需要）：

```powershell
cd _dev
npm install jsdom --no-save --no-audit --no-fund --cache .\.npm-cache
```

（`--cache` 指到项目文件夹里，是因为这台机器的全局 npm 缓存目录在沙箱外，装的时候会报 EPERM。）

然后：

```powershell
node _dev/test-store.js     # 数据层：日期口径、连续天数、统计聚合、导入导出、脏数据（28 项）
node _dev/test-ui.js        # 界面层：四个页面渲染、记录全流程、删除、设置编辑、空状态（75 项）
node _dev/test-multi.js     # 多项目：增删改归档、记录归属、范围过滤、统计隔离、旧数据迁移（186 项）
node _dev/test-labels.js    # 标签增删：自定义/内置原因与场景的加、删、恢复、脏数据、历史记录不受影响（81 项）
node _dev/check-desktop.js  # 分栏结构、手机顺序、备份提醒、manifest/图标、SW 注册与预缓存（62 项）
node _dev/check-css.js      # 静态：CSS 括号配平、JS 里用到的 class 是否有定义
node _dev/check-fresh.js    # 全新用户（localStorage 为空）首次打开看到什么
```

这些脚本用 jsdom 真的执行 `index.html` 里的脚本，所以能抓到真实的运行时报错。`_dev` 整个目录删掉不影响使用。

注意：jsdom 只能验证 DOM 结构和文案，**验证不了真实排版**。视觉调整仍然要在浏览器里看。

还有一份**真浏览器**的检查——jsdom 不支持 service worker，所以「改了文件 → 重开 → 拿到新版」这条链路只能用真 Chromium 验：

```powershell
python -m http.server 8123 --bind 127.0.0.1   # 另开一个窗口
python _dev/pwa-probe.py                       # 需要 python + playwright（这台机器已有）
```

它会起页面、等 SW 接管、往 `js/store.js` 尾巴塞一个标记模拟「我改了一版」，再重开页面确认拿到新版、新内容写回了缓存、断网后仍能打开（10 项）。
